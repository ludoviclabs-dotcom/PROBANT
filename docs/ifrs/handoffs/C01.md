## 3. Contrat des nouvelles données

### 3.1 Virgule fixe (`Fixed`)

- `bigint` à l'échelle 10⁴⁰, marqué par un type distinct : un taux ou un facteur n'est jamais un `Money`.
- Entrée d'un taux : `parseRate` accepte une fraction décimale de 0 à 1, au plus 30 décimales. Il refuse une chaîne vide, un espace, un signe, un exposant, une virgule ou un nombre JavaScript (`L16_RATE_INVALID`).
- Relecture exacte : `formatFixed` écrit toujours 40 décimales ; `parseFixed` relit sans perte et refuse `-0` et l'exposant.
- Vers le centime, un seul passage : `toCents`, moitié à l'opposé de zéro.

### 3.2 Contexte, manifeste, fiche de règle

- `IfrsContext` = périmètre serveur + exercice + référentiel déclaré + première application `not_applicable` (X32). `assertIfrsContext` refuse un autre dossier, une autre organisation, un autre mode (`WORKPAPER_SCOPE_MISMATCH`), un autre exercice (`WORKPAPER_PERIOD_INVALID`), une juridiction ou une norme hors liste (`L16_REQUEST_INVALID`).
- `frameworkBlockers` : la juridiction `EU_adopted` n'est pas activable en réel (X33). Elle reste admise en scénario.
- `PreparationManifest` (C00 § 4.3) et `assertManifestFor` :
  - retraitements inclus inconnus → `L16_BASE_UNKNOWN` ;
  - autre nature de base ou autres sources → `L16_BASE_MISMATCH` (code ajouté) ;
  - autre exercice → `L16_PERIOD_MISMATCH`.
- `LeaseRuleBasis` : `validated` exige un relecteur nommé et une date ; `review_required` n'en porte pas.

### 3.3 Retraitement (`AdjustmentBundle`)

| Partie | Contenu | Empreinte |
|---|---|---|
| Contenu (`AdjustmentBundleCore`) | Lignée (`logicalId`, révision, `runId`), périmètre, exercice, base attendue, identités triées, lignes débit / crédit, contributions de résultat, `taxStatus: "not_computed"` | `bundleHash`, stable de l'approbation au verrouillage |
| Matérialisation | `runVersion`, `contentHash` et `status` (`proposed` / `reviewed`) lus sur la version exacte de la feuille | — |

Invariants vérifiés par `assertBundleCore` :
- **`L16_BUNDLE_UNBALANCED`** : débit ≠ crédit au centime, par contrat comme au total ;
- **`L16_BUNDLE_INVALID`** (code ajouté) :
  - montant nul ou négatif, ou compte hors liste (donc aucune ligne de trésorerie possible) ;
  - identités non triées, en double ou sans lignes ;
  - contribution absente ou différente du solde des lignes de résultat ;
  - nature incohérente avec un compte de résultat ou d'effet d'ouverture ;
  - empreinte annoncée différente de l'empreinte recalculée.

Les 17 retraitements calculés de l'oracle C00 passent ces invariants.

### 3.4 Sélection (`decideBundleSelection`), logique pure pour le journal C14

- Feuille ni approuvée ni verrouillée → `L16_BUNDLE_NOT_REVIEWED`.
- Version, empreinte, lignée, source ou règle différente de la version exacte → `L16_BUNDLE_STALE`.
- Base ou autre lignée qui inclut déjà une identité → `L16_BUNDLE_ALREADY_INCLUDED`.
- Même lignée, révision et version avec un autre contenu → `L16_BUNDLE_CONTENT_CONFLICT`.
- Scénario ou autre dossier → `WORKPAPER_SCOPE_MISMATCH`.
- Rejeu : aucun changement, aucun doublement. Nouvelle version de la même lignée : elle remplace la précédente.
- `selectionStanding` ne marque « à réexaminer » que la sélection dont la feuille a changé. Un verrouillage après l'approbation ne périme rien, car le contenu est identique.

### 3.5 Dépendances (`dependencyFingerprint`, `compareFingerprints`)

- Composantes séparées : sources, mapping, politique, règle.
- Une empreinte par contrat (contrat + politique + règle) : un contrat modifié ne touche que lui ; une politique ou une règle modifiée touche tous les contrats.
- Pur : consulter ne périme rien.

### 3.6 Travail de la feuille (`LeaseWork`, `ifrs16-leases-1`)

- Champs : référentiel, première application, politiques par catégorie d'actif (`short_term_exemption`, `non_lease_components_election`, `vat_treatment`), confirmations par contrat et par champ.
- Chaque réponse est `value` (chaîne non vide), `unknown` (motif) ou `not_applicable` (motif) : vide ≠ zéro ≠ non applicable.
- Auteur et date posés par le serveur ; aucun rôle ni auteur accepté du navigateur.
- Citation `{ documentVersionId, rowId }` résolue par le serveur sur une ligne approuvée : avant le gel parmi les têtes courantes, après le gel parmi les sources figées (`L16_CITATION_INVALID`).
- Le dictionnaire des champs confirmés relève de L16-01.

### 3.7 Sources `lease_*` (mapping fermé `ifrs16-leases-1`)

- Colonnes `Key;Amount;Date;Details`. `Details` est un objet JSON fermé : `contractId`, `source` (titre, pack, date ≤ date de revue, page, clause) et `fields` (chaînes non vides seulement).
- `lease_contracts` : la clé est l'identifiant du contrat, unique (`L16_DUPLICATE_CONTRACT`). Le montant est la somme des loyers fixes non actualisés déclarée par la pièce, jamais négative (`L16_CONTRACT_INVALID`).
- Les autres types nomment leur contrat ; le grand livre peut porter des lignes non rattachées.
- Population `lease_contract` : une ligne du registre des contrats = un élément.
- Les colonnes propres à chaque type sont fermées en L16-01.

## 10. Pièges relevés

1. **Store append-only** : `clients_workpaper_versions` refuse toute mise à jour (`CLIENTS_APPEND_ONLY`). Pour simuler une feuille ancienne, on insère une nouvelle tête, on ne réécrit jamais.
2. **`importIds` est trié** par la population au gel : comparer des listes triées.
3. **Recette d'une feuille voisine** : elle n'est probante que sur le même dossier **et** le même exercice, donc la même table de têtes. Le jeu Locations est sur l'exercice 2026 d'Emprunts pour cette raison.
4. **`evaluation.observations` du dossier de clôture** est la liste brute : sans filtre dans `cycleRuns`, une feuille de référentiel y apparaîtrait.
5. **Heredoc Bash** : une séquence `\\n` dans un script Python inline est altérée. Écrire le script dans un fichier.
6. **Worktree sans `node_modules`** : `npm ci` (≈ 2 min) plutôt qu'une jonction vers un autre worktree.
