## 3. API de sélection (pour L16-04, et pour P18-05 si IFRS 18 est engagé)

- `selection-url.ts` (module pur, lu aussi par la page serveur) : `LeaseSelectionState = { contractId, column, filter }`, `parseSelection(search)` et `selectionSearch(base, state)`. Paramètres d'URL : `contrat`, `colonne`, `filtre`. Une valeur inconnue est ignorée, jamais devinée.
- `useLeaseSelection(initial)` → `{ selection, open(contractId, column), close(), filter(f) }` :
  - ouvrir un objet ajoute une entrée d'historique ; filtrer remplace l'URL ;
  - le retour arrière restaure l'état.
- La sélection et les filtres ne touchent ni la population figée, ni la version revue, ni un export. Le texte « Affichage filtré : n contrats sur N — la population figée et l'export ne changent pas » le rappelle à l'écran.

## 7. Non vérifié, limites

- **Parcours réel connecté** (profil local, base, session) : non joué en e2e. La recette PostgreSQL couvre la chaîne serveur, pas l'écran connecté. `e2e/c07-profil-local.spec.ts` attend désormais 16 liens ; il n'est joué qu'avec un profil local démarré, donc non vérifié ici.
- **États non capturés** : écrans d'import en traitement et d'import rejeté, de conflit de version et de source remplacée. Ils sont codés (`StateNotice`, `SourcesPanel`) et leurs conditions sont testées au niveau du modèle de vue et du serveur, mais pas captés en image.
- **Zoom 200 %** : approché par une largeur de 720 px, et non par un zoom réel du navigateur.
- **Lecteurs d'écran** : aucun parcours réel avec lecteur d'écran ; axe ne suffit pas à déclarer une accessibilité exhaustive.
- **Mode développement** : le garde de chargement initial devait se réarmer, parce que React y monte les effets deux fois (corrigé). Le même motif semble présent dans `LoanWorkspace` (garde `autoLoaded`) ; non vérifié et non modifié ici.
