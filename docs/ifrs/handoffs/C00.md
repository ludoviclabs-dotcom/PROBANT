## 8. Pièges relevés pour C01

1. **`store-readers.ts:13`.** `CAPABILITY_STORE_PROCEDURE_MISMATCH` est levé pour toute feuille du store « clients » dont la procédure n'est pas enregistrée. Une première feuille `ifrs16.leases` casserait la lecture du dossier de clôture si l'axe « référentiel » n'y est pas reconnu.
2. **`service.ts`.** La liste des adaptateurs réels existe en **trois** exemplaires : le type du constructeur (l. 50), `actor()` (l. 53) et `lock()` (l. 357). Les trois doivent recevoir `ifrs16.leases`.
3. **`clients-persistence.ts:37`.** Liste blanche des gabarits du store « clients ».
4. **`imports.ts`.** La porte de `previewImport` croise adaptateur, version du mapping et type de document. Sans entrée, l'erreur est `REAL_IMPORT_STORAGE_DISABLED`.
5. **Tests figés** : `registry.test.ts` (18 procédures, version `1.4.1`), `profile.test.ts` avec `scripts/local/local-lib.mjs` (« quatorze » drapeaux), `c15-matrice.test.ts` (la page de chaque route doit exister), `e2e/c07-profil-local.spec.ts` (15 liens). Les mettre à jour sans assouplir leur intention.
6. **`review-kind.ts`.** `approvalLabel` utilise `toLocaleString`, dont le résultat dépend du fuseau : à éviter dans l'export L16.
7. **Migration `0022`.** Le `down` doit refuser le retour en arrière en présence de données (modèle `0021`). Elle se teste sur une base jetable identifiée, jamais sur la base personnelle.

**Recette C01 minimale** :
- gros montants sans perte ;
- zéro connu, inconnu, non applicable et vide distincts ;
- entité ou période erronée rejetée sans écriture partielle ;
- rejeu idempotent, et conflit si la charge diffère ;
- deux modifications concurrentes : une seule réussit ;
- retraitement déséquilibré, déjà inclus, périmé ou sur une mauvaise base : refusé ;
- source remplacée : seule la lignée concernée est à réexaminer ;
- échec en cours de transaction : aucune publication ;
- **le dossier de clôture et les autres cycles se lisent à l'identique avec une feuille `ifrs16.leases` présente**.
